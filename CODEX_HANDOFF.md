# Codex handoff — iFCM expert-panel study

Updated 25 October 2026. This is the **single starting document** for a new Codex session working on the current ISBI-workshop-oriented A/B1/B2 study. Read it before changing code or quoting a result. All paths below are relative to this file's directory unless stated otherwise.

## 1. What this study asks

Can a diagnosis system benefit from explicitly propagating uncertainty about (a) clinical findings predicted from images and (b) finding-to-diagnosis links elicited from large language models? The project studies lung nodules (LIDC-IDRI) and skin lesions (Derm7pt). It compares three reasoning methods on **the same aligned examples, image predictions, and LLM panel**:

| Name | Meaning |
| --- | --- |
| **A** | Existing scalar weighted sum: predicted finding strengths multiplied by fixed, signed LLM-edge weights. |
| **B1** | Signed intuitionistic-fuzzy reasoning with intervals around the predicted image findings, but fixed point-estimate LLM edges. |
| **B2** | The same reasoning as B1, additionally using heuristic intervals around LLM edges. |

The image model sees each patient's image. The LLMs **do not see individual patient images**; they answer generic clinical finding-to-diagnosis questions. For example, the image model estimates whether a CT nodule looks spiculated, and the LLM panel estimates how spiculation supports or opposes malignancy. The diagnosis model combines these two sources.

The scientific hypothesis is a comparison, **not** a promise that B1/B2 will improve A. The intuitionistic operator is a proposed research adaptation for signed clinical edges, not an established clinical rule.

## 3. Mathematical and implementation contract

Let `X` be mean predicted finding scores with shape `(N,C)` and `W` the full-precision signed panel-mean edges with shape `(C,D)`, in `[-1,1]`. A uses `Z=X@W`, then fits an independent two-parameter logistic calibrator for each diagnosis: `p_d=sigmoid(a_d Z_d+b_d)`. The slopes/intercepts are fitted only on the approved fit cases. This Model A is implemented as an adapter in `ifcm/comparison.py`; do not silently change it.

For B1/B2, finding draws have shape `(N,C,S)` (`S=5` LIDC seeds or `S=30` Derm probe draws). A heuristic 10th/90th-percentile envelope, expanded to include the draw mean, gives `[xL,xU]`. Its intuitionistic-fuzzy value is `(mu_x,nu_x,pi_x)=(xL,1-xU,xU-xL)`. This is **not** a calibrated confidence or credible interval. B1 sets both edge endpoints equal to `W`.

B2 reconstructs each aligned member edge `w_m` and unsure score `u_m` from saved votes. It uses `W=mean_m(w_m)`, `h=mean_m(u_m)+sample_SD_m(w_m)`, and edge interval `[clip(W-h,-1,1),clip(W+h,-1,1)]`. This is a disagreement/unsure **heuristic**, not a statistically calibrated edge interval. B2 with zero edge width must equal B1 exactly.

For each finding-to-diagnosis link, positive evidence is `pL=xL max(wL,0)`, `pU=xU max(wU,0)`; opposing evidence is `rL=xL max(-wU,0)`, `rU=xU max(-wL,0)`. Aggregate each endpoint across concepts with `OR(q)=1-product_c(1-q_c)`, giving `PL,PU,RL,RU`. The proposed conflict projection is:

```text
mu_d = PL * (1-RU)
nu_d = RL * (1-PU)
pi_d = 1-mu_d-nu_d
s_d  = mu_d-nu_d
```

Calibrate `s_d` with **one slope and one intercept per diagnosis**, matching A's calibration capacity. LIDC uses the two calibrated MAL/BEN scores to form `p_MAL/(p_MAL+p_BEN)` and predicts malignancy above 0.5. Derm uses the argmax of four independently calibrated scores. These are implemented in `ifcm/intuitionistic_reasoning.py`, `ifcm/b1.py`, `ifcm/b2.py`, and `ifcm/b1_inputs.py` / `ifcm/b2_inputs.py`. `docs/intuitionistic_reasoning_spec.md` contains further derivations and edge cases. Diagnosis `pi` can include lack of evidence or conflicting evidence even when input intervals have zero width; it is **not** itself a probability of error.

The test prediction bundles for `a/`, `b1/`, and `b2/` are aligned by ordered `ids`, `patients`, `split`, `fold`, `concepts`, `diagnoses`, and `finding_mean`. They contain fit/test predictions separately and no test labels. Manifests hash source inputs, code, predictions, and outputs. Never change a hashed source module and then claim the saved results were produced by the changed code.

### Additional exploratory analysis: where hesitation comes from

`ifcm/source_uncertainty.py` computes four IFS states—neither input interval, finding interval only, edge interval only, and both—and splits the *increment* over baseline hesitation between image findings and LLM edges using the average of the two addition orders. It scores Model A's frozen predicted class throughout. Outputs are in each run's `source_uncertainty_v1/` (`case_scores.csv`, `score_metrics.csv`, `paired_auc.csv`, `triage.csv`, `summary.json`, `manifest.json`). To repeat it, first build a **separate, complete** A/B1/B2/evaluation run, then use `../.venv-repro/bin/python -m ifcm.source_uncertainty --dataset lidc --run-id THAT_NEW_RUN_ID` or the analogous Derm command. Do **not** run it on the existing run IDs because this module refuses to overwrite existing output. Read `RESULTS.md` and the CSVs for the completed results.

In brief, mean total hesitation was 0.9864 LIDC / 0.9776 Derm; the edge-interval increment was about 0.4620 / 0.4516 versus image increment 0.0712 / 0.0506. Total hesitation detected A errors at AUROC 0.4696 / 0.5019, worse than A's plain low-confidence score at 0.7272 / 0.7160. Source-balance did **not** reliably improve perception-versus-knowledge attribution over the existing decision-flip score. Fit-quantile referral thresholds were also tested, but their achieved test coverages differ. This analysis was designed after primary test results were known: **post-hoc, exploratory, not confirmatory**. The large edge increment reflects the specified heuristic scale, not proven clinical knowledge uncertainty.

## 6. Commands that are safe for a new session to check

Run from the repository root. The existing downstream Python is `../.venv-repro/bin/python`; the fuller PyTorch environment is `.venv-upstream/bin/python`. If the downstream environment is missing, create it with `python3 -m venv ../.venv-repro` followed by `../.venv-repro/bin/python -m pip install -e . -r requirements-repro.txt`.

Read-only saved-result verification:

```bash
P=../.venv-repro/bin/python
for entry in 'lidc isbi-b1-lidc-v1' 'derm isbi-b1-derm-monet-v1'; do
  set -- $entry
  for module in b1 b2 comparison supplementary paper_outputs; do
    "$P" -m "ifcm.$module" --dataset "$1" --run-id "$2" --verify
  done
  "$P" -m ifcm.comparison --dataset "$1" --run-id "$2" --parity
  "$P" -m ifcm.evaluate_comparison --dataset "$1" --run-id "$2" --summary
done
"$P" -m ifcm.safe_cnn verify-boundary --run-id isbi-lidc-strict-v3 --dry-run
.venv-upstream/bin/python -m unittest discover -s tests
```

This verification passed on 25 October 2026 for both datasets and the CNN boundary; the unit suite ran 38 tests with one skip. The same commands should be rerun after any environment change. They do not train a model.

## 7. Research and operational constraints

1. **Distinguish saved-input downstream reproduction from a raw-data, all-model rerun.** The latter is not yet guaranteed. LIDC crop inputs and an ImageNet checkpoint may depend on machine-local `/var/tmp`; model caches there are temporary. The saved CNN predictions and manifests are the current comparison inputs.
2. **Protect the evaluation boundary:** no test labels for fit, interval selection, model choice, or calibration; preserve LIDC patient grouping. The method design had prior exposure to earlier exploratory outcomes, so the strict CNN split does not make the entire research program prospectively untouched.
3. **Preserve provenance:** keep original input CSV/NPZ, official split metadata, strict CNN run, A/B1/B2 manifests, `evaluation_v2/`, `supplementary_v1/`, and `paper_v4/`. Never overwrite a verified run. Keep new outputs under distinct run IDs.
4. **Do not overclaim:** B1's LIDC advantage is inconclusive; no patient-level Derm CI exists; IFS hesitation is not calibrated error probability; edge-disagreement labels are not clinical ground truth; decision-flip attribution is operational, not causal proof. Runtime was not logged, so no runtime comparison is supported.
5. **When asked for a change, work narrowly:** inspect the relevant modules/manifests, make only the requested change, run lightweight static/synthetic or read-only checks, and give exact user-run commands for anything expensive. Do not launch GPU inference, dataset downloads, or ten-LLM regeneration without an explicit request.

For exact numbers, read the CSVs, not this rounded handoff table. For the derivation of the IFS operator, see `docs/intuitionistic_reasoning_spec.md`. This handoff is the overview and reproducibility map; those files are the machine-checkable evidence.
